# Identity service

Identity combines authentication, users, credentials, roles and sessions in one PostgreSQL database. There are no credential HTTP endpoints or calls to the former User service.

## Run

Java 17, PostgreSQL and the RSA key pair generated by the repository script are required. Set DB_URL, DB_USERNAME, DB_PASSWORD, JWT_PRIVATE_KEY_BASE64 and JWT_PUBLIC_KEY_BASE64, then run `gradlew.bat bootRun`, or use root Docker Compose. Keys must be a matching RSA pair of at least 2048 bits. Private key is PKCS#8 DER/base64; public key is X.509 DER/base64.

Flyway V1/V2 are preserved unchanged. V2 adds users, credentials, roles, role links, sessions, refresh tokens and a minimal transactional outbox. Spring Data JPA/Hibernate maps that schema with `ddl-auto: validate` and `open-in-view: false`; Flyway alone owns schema changes. Role IDs are 1=USER and 2=ADMIN. Email and optional username are stored lowercase with database uniqueness.

Entities map user-role membership, shared-key user credentials, sessions and refresh tokens. Services use `@Transactional`, repository queries and managed-entity dirty checking; no production JdbcTemplate or hand-written CRUD SQL remains. User `@Version` detects stale writes. Outbox events are recorded after flushing the aggregate so their version matches the persisted user. Refresh acquires pessimistic locks in user/session/token order; its initial lookup uses a scalar projection so a waiting transaction does not reuse an old token entity. Bulk session revocation uses JPQL and is limited to paths that have not loaded session entities. Profile/role mapping happens inside transactions with OSIV disabled.

Bootstrap is opt-in through BOOTSTRAP_ADMIN_ENABLED, BOOTSTRAP_ADMIN_EMAIL and BOOTSTRAP_ADMIN_PASSWORD. It creates an admin only when no active admin exists, never promotes an existing account or replaces its password. A collision fails startup. Disable bootstrap after provisioning.

## HTTP contract

Responses use {status_code, success, message, data}, except the OAuth form endpoint (raw token), paginated listing (additional pagination) and deletes (204).

| Method | Path under /api/v1 | Access / request |
|---|---|---|
| POST | /auth/register | Public; email, password, optional username; always USER |
| POST | /auth/login | Public; email, password |
| POST | /auth/login/access-token | Public; form username=email and password; legacy compatibility |
| POST | /auth/refresh-token | Public; refresh_token |
| POST | /auth/logout | Public; refresh_token; idempotently revoke its session |
| POST | /auth/logout-all | Bearer; revoke every session of caller |
| GET | /users/me | Bearer; profile |
| PATCH | /users/me | Bearer; username, full_name |
| DELETE | /users/me | Bearer; soft delete, revoke sessions |
| POST | /users/me/password | Bearer; current_password, new_password; revoke all sessions |
| GET | /users | ADMIN; page=0, size=20 (maximum 100), fixed stable ordering |
| POST | /users | ADMIN; email, password, optional username, roles=[1,2] |
| GET | /users/{uuid} | Owner or ADMIN |
| PATCH | /users/{uuid} | ADMIN; is_active, full_name, roles=[1,2] |
| DELETE | /users/{uuid} | ADMIN; soft delete |
| GET | /actuator/health | Public health endpoint |

Token responses contain access_token, refresh_token, token_type=bearer and expires_in in seconds. Public refresh/logout should be called without an expired Authorization header. Passwords must have at least 8 characters and at most 72 UTF-8 bytes (bcrypt limit); legacy bcrypt hashes are supported.

The last active administrator cannot be disabled, deleted or demoted. User details are restricted to owner/admin, tightening the old authenticated-any-user lookup. No by-email/by-username public lookup or /api/internal credential endpoints are exposed. Registration returns the user object as the former Java Auth service did; clients using monolith message-only responses should adapt.

## Session semantics

Access JWT uses RS256, sub=user UUID, roles=ROLE_USER/ROLE_ADMIN, sid, jti, iss, aud, iat, exp. Default access lifetime: 900 seconds; session lifetime: 7 days, absolute rather than sliding. Refresh tokens are random 256-bit opaque values, stored only as SHA-256 hex digests.

Refresh locks the user and session; one concurrent refresh succeeds, reuse revokes the entire family and commits the revocation even though HTTP returns 401. A client must serialize refresh and must not automatically retry an old token after an uncertain response; re-login is required if the new token was lost. Keep used token rows while their session could still be active.

Identity validates the session and current database roles on every authenticated request. Logout, account disable, role change and password change therefore take effect immediately inside Identity. Gateway and other services that only verify JWT signatures can still accept a previously issued access token until expiration. Global immediate revocation requires the later event/cache integration; this implementation does not claim it.

Outbox contains PII-free user ID notifications in the same transaction as account writes. Relay, versioned projection snapshots and RabbitMQ delivery are deferred to the event phase; do not configure consumers against these minimal notifications yet. Digests are hex varchar rather than bytea and payload is JSON text rather than jsonb; the design document is logical, V2 is the implemented schema.

## Verification

Run `gradlew.bat test bootJar`. HTTP integration tests start the full server, execute Flyway migrations against H2 PostgreSQL mode and cover security, unique constraints, session rotation/concurrency and account administration. They do not substitute for PostgreSQL migration and Docker deployment checks.

## Import users from Python monolith

Run only during a scheduled account-write freeze, after backup/restore rehearsal, against an empty Identity account database. Disable bootstrap first. The script refuses a populated users table and rolls back on collisions or invalid source records. It does not import from the separate legacy Java User DB; that deployment requires its own mapping.

Export with psql connected to the monolith database:

```sql
\copy (SELECT id,email,hashed_password,is_active,full_name,role,created_at,updated_at FROM "user") TO 'users.csv' WITH (FORMAT csv, HEADER true)
```

From the directory containing users.csv, run psql against the Identity database with `-v ON_ERROR_STOP=1 -f <absolute-path>/identity-service/scripts/import-monolith-users.sql`. Use secure local credential configuration; avoid passwords in shell arguments. CSV contains credential hashes: restrict access and remove it securely after verified import.

Verify row counts/IDs, roles and representative bcrypt login fixtures before switching traffic. Existing usernames are absent in the monolith and stay null. Existing JWTs and refresh tokens are not migrated; users must log in again. This script has not been run against user data in this task.

Former Auth/User source is recoverable from Git history once removed. Rollback routing to those services requires their previous images and compatible databases; switching back after Identity accepts new writes requires data reconciliation, not just changing the route.
