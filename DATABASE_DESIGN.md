# Thiết kế database theo service

Trạng thái: thiết kế đề xuất, ngày 2026-09-22. Chưa áp dụng DDL hoặc chuyển dữ liệu. Các migration V1 hiện chỉ chứa `service_metadata`; triển khai nghiệp vụ bằng migration mới, không sửa migration đã chạy. Thiết kế cập nhật phạm vi storage so với scaffold: Search và Ingestion cần PostgreSQL riêng khi triển khai consumer/job bền vững, chưa có trong Compose hiện tại.

## 1. Ranh giới và quy ước

| Service | Storage | Nguồn dữ liệu chính |
|---|---|---|
| Identity | PostgreSQL `mytruyen_identity` | Tài khoản, credential, role, phiên đăng nhập |
| Catalog | PostgreSQL `mytruyen_catalog` | Truyện, tác giả, phân loại, chương và nội dung |
| Engagement | PostgreSQL `mytruyen_engagement` | Bình luận, đánh giá, bookmark, thống kê tương tác |
| Search | Meilisearch + PostgreSQL `mytruyen_search` | Projection có thể dựng lại; không sở hữu truyện |
| Ingestion | PostgreSQL `mytruyen_ingestion` + RabbitMQ | Job, checkpoint, lịch sử chạy |
| Gateway | Không có relational DB; Redis khi triển khai rate limit | Dữ liệu tạm, có TTL |

Các database có credential riêng, không đọc chéo hoặc tạo FK xuyên database. Có thể đặt chung PostgreSQL instance lúc nhỏ; tách database không bắt buộc tách máy chủ. Redis và RabbitMQ không thay thế database lưu trạng thái nghiệp vụ.

Quy ước dưới đây: `PK` là khóa chính, `FK` là khóa ngoại nội bộ, `UQ` là unique; `?` nghĩa là nullable, các cột còn lại NOT NULL. Bảng nghiệp vụ có `created_at`, `updated_at` kiểu `timestamptz` UTC; bảng chỉ ghi thêm chỉ cần `created_at`. `version bigint DEFAULT 0` dùng cho optimistic locking tại các aggregate được chỉ định. Thay đổi version phải được thực hiện cả ở đường ghi ORM lẫn SQL trực tiếp.

- Giữ UUID của user, author, comment, review để chuyển dữ liệu không đổi identity.
- Book, chapter, taxonomy dùng `bigint GENERATED BY DEFAULT AS IDENTITY`; giữ ID integer cũ và nâng khả năng chứa. Sau import phải cập nhật sequence lên trên MAX(id).
- Các external ID dùng đúng kiểu nguồn: user UUID, book/chapter bigint.
- Trạng thái hữu hạn dùng varchar + CHECK, tránh tạo enum PostgreSQL khi tập giá trị còn có thể đổi.
- Mọi index ngoài PK/UQ bên dưới là index bổ sung cho truy vấn cụ thể; không tạo trùng index mà unique constraint đã có.

## 2. Identity

| Bảng | Cột chính | Constraint / index |
|---|---|---|
| `users` | `id uuid PK`, `email varchar(254)`, `username varchar(50)?`, `full_name varchar(255)?`, `is_active boolean DEFAULT true`, `deleted_at timestamptz?`, `version bigint` | UQ expression `lower(email)`; UQ `lower(username)` WHERE username IS NOT NULL |
| `user_credentials` | `user_id uuid PK/FK users`, `password_hash text`, `password_changed_at timestamptz` | Quan hệ 1:1; hash có thông tin thuật toán/định dạng, không lưu plaintext |
| `roles` | `id smallint PK`, `code varchar(32) UQ` | Seed `USER`, `ADMIN`; map sang claim/authority theo contract JWT |
| `user_roles` | `user_id uuid FK users`, `role_id smallint FK roles` | PK `(user_id, role_id)`; index `(role_id, user_id)` |
| `auth_sessions` | `id uuid PK`, `user_id uuid FK users`, `expires_at timestamptz`, `revoked_at timestamptz?`, `device_label varchar(255)?` | Index `(user_id, created_at DESC)`; CHECK expiry > creation |
| `refresh_tokens` | `id uuid PK`, `session_id uuid FK auth_sessions`, `token_hash bytea UQ`, `expires_at timestamptz`, `used_at timestamptz?`, `revoked_at timestamptz?` | Index `session_id`, `expires_at`; CHECK expiry > creation |

Username nullable vì monolith không có username; không bắt người dùng cũ mất khả năng đăng nhập. Chuẩn hóa email bằng trim/lower trong application và kiểm tra uniqueness ở DB; báo cáo collision trước import. Giữ nguyên bcrypt hash cũ và kiểm tra tương thích encoder Java bằng fixture trước cutover.

Một session là một token family của một lần đăng nhập/thiết bị. Khi refresh, khóa session/token trong transaction, kiểm tra user active và hạn session/token, đánh dấu token cũ đã dùng rồi tạo token mới. Token opaque có entropy cao, DB chỉ lưu digest; reuse token đã dùng sẽ revoke cả session. Giữ record token đã dùng ít nhất đến khi session hết hiệu lực để phát hiện reuse. Không phát event chứa hash password hoặc token.

Đổi mật khẩu/khóa tài khoản thu hồi session và phát event cùng transaction. Access JWT đã phát vẫn có thể còn hiệu lực tới exp; yêu cầu khóa tức thời cần thêm revocation check/cache tại service, không được giả định cập nhật DB tự vô hiệu hóa JWT. Physical purge user mới cascade credential/session/token/user_roles; thao tác khóa/xóa tài khoản thông thường không xóa truyện của user.

## 3. Catalog

| Bảng | Cột chính | Constraint / index |
|---|---|---|
| `authors` | `id uuid PK`, `name varchar(255)`, `local_name varchar(255)?`, `avatar_url text?`, `version bigint` | Index `name`; không unique tên vì có thể trùng bút danh |
| `book_statuses` | `id bigint PK`, `slug varchar(100) UQ`, `name varchar(100)`, `description text?` | Trạng thái sáng tác, độc lập với trạng thái công khai |
| `genres` | `id bigint PK`, `slug varchar(150) UQ`, `name varchar(150)`, `description text?` | Không dùng tên hiển thị làm identity |
| `tags` | `id bigint PK`, `slug varchar(150) UQ`, `name varchar(150)`, `type varchar(50)`, `description text?` | Index `(type, id)` |
| `books` | `id bigint PK`, `author_id uuid? FK authors`, `creator_id uuid`, `status_id bigint FK book_statuses`, `name varchar(500)`, `slug varchar(500) UQ`, `kind integer`, `sex integer`, `synopsis text`, `poster jsonb?`, `note text?`, `chapter_per_week integer DEFAULT 0`, `published boolean DEFAULT false`, `published_at timestamptz?`, `deleted_at timestamptz?`, `version bigint` | Index author/creator/status; CHECK chapter_per_week >= 0; partial index `(published_at DESC, id DESC)` WHERE published AND deleted_at IS NULL |
| `book_genres` | `book_id bigint FK books`, `genre_id bigint FK genres` | PK `(book_id, genre_id)`; index `(genre_id, book_id)` |
| `book_tags` | `book_id bigint FK books`, `tag_id bigint FK tags` | PK `(book_id, tag_id)`; index `(tag_id, book_id)` |
| `chapters` | `id bigint PK`, `book_id bigint FK books`, `creator_id uuid`, `chapter_index integer`, `name varchar(500)`, `word_count bigint DEFAULT 0`, `published boolean DEFAULT false`, `published_at timestamptz?`, `deleted_at timestamptz?`, `version bigint` | UQ `(book_id, chapter_index)`; CHECK index > 0, word_count >= 0; partial index `(book_id, chapter_index)` WHERE published AND deleted_at IS NULL |
| `chapter_contents` | `chapter_id bigint PK/FK chapters`, `content text`, `content_hash varchar(64)`, `version bigint` | Một chapter tối đa một content; chapter chỉ được publish khi có content |
| `book_content_stats` | `book_id bigint PK/FK books`, `chapter_count bigint`, `word_count bigint`, `latest_chapter_index integer?`, `new_chap_at timestamptz?` | CHECK counts >= 0; index `(new_chap_at DESC, book_id DESC)` |
| `book_engagement_projection` | `book_id bigint PK/FK books`, `view_count bigint`, `comment_count bigint`, `review_count bigint`, `rating_sum bigint`, `bookmark_count bigint`, `source_version bigint` | CHECK counts >= 0; index `(view_count DESC, book_id DESC)` khi có top view API |

`kind` và `sex` giữ mã legacy trong đợt chuyển đầu; phải thống kê và xác nhận ý nghĩa mã trước thêm CHECK hoặc đổi tên thành audience. `poster` giữ JSON tương thích dữ liệu cũ, application validate cấu trúc; file ảnh nằm trong object storage/CDN, không lưu blob vào PostgreSQL.

Catalog giữ book/chapter cùng DB vì tạo/sửa/xóa chương, đếm chương và publish cần transaction nội bộ. Nội dung TEXT tách 1:1 để API danh sách chương không tải nội dung dài. Không cần chuyển nội dung sang object storage ở giai đoạn này.

`chapter_count`/`word_count` trong stats được định nghĩa cho chương public chưa xóa; nếu admin cần tổng draft thì query riêng. Publish/unpublish/edit nội dung phải khóa hoặc cập nhật atomically stats, ghi outbox cùng transaction. `latest_chapter_index` là MAX index chương public, lấy chapter bằng `(book_id, chapter_index)`; bỏ field UUID `latest_chapter` sai kiểu của monolith. `new_chap_at` là thời điểm publish mới nhất còn hiệu lực; recompute khi unpublish/delete. Không bắt buộc lưu pointer FK tạo vòng book -> chapter -> book.

Stats tương tác trong Catalog chỉ là bản sao từ Engagement để lọc/sắp xếp danh sách không gọi nhiều service. Không dùng `average_rating` dạng float làm nguồn dữ liệu chính: tính `rating_sum / review_count`, trả null hoặc 0 theo API khi chưa có review. Chọn event snapshot stats đầy đủ với source_version tăng đơn điệu, không cộng lại delta khi replay.

Xóa mềm book/chapter trước, phát event; purge là job riêng sau thời gian giữ dữ liệu. Physical purge cascade link bảng phân loại, chapter/content/stats; xóa taxonomy đang được dùng phải RESTRICT hoặc chuyển liên kết trước. Tất cả FK trong phần này nội bộ Catalog; creator_id không FK tới Identity.

## 4. Engagement

Giả định sản phẩm đề xuất: mỗi user có một đánh giá cho mỗi book, thang điểm nguyên 1–5, bình luận gắn chapter, một bookmark cho mỗi user/book. Đây là quyết định mới; dữ liệu review cũ chưa có CHECK thang điểm nên cần audit trước migration.

| Bảng | Cột chính | Constraint / index |
|---|---|---|
| `book_refs` | `book_id bigint PK`, `published boolean`, `deleted boolean`, `source_version bigint` | Projection từ Catalog; không lưu content |
| `chapter_refs` | `chapter_id bigint PK`, `book_id bigint FK book_refs`, `published boolean`, `deleted boolean`, `source_version bigint` | UQ `(chapter_id, book_id)`; index book_id |
| `comments` | `id uuid PK`, `user_id uuid`, `book_id bigint`, `chapter_id bigint`, `parent_id uuid?`, `content text`, `status varchar(20)`, `version bigint` | FK `(chapter_id, book_id)` -> chapter_refs; UQ `(id, chapter_id)`; FK `(parent_id, chapter_id)` -> comments; CHECK parent_id <> id, status IN ('VISIBLE','HIDDEN','DELETED') |
| `reviews` | `id uuid PK`, `user_id uuid`, `book_id bigint FK book_refs`, `rating smallint`, `content text?`, `version bigint` | UQ `(user_id, book_id)`; CHECK rating BETWEEN 1 AND 5; index `(book_id, created_at DESC, id)` |
| `bookmarks` | `user_id uuid`, `book_id bigint FK book_refs` | PK `(user_id, book_id)`; index `(user_id, created_at DESC, book_id)` và book_id |
| `book_stats` | `book_id bigint PK/FK book_refs`, `view_count bigint`, `comment_count bigint`, `review_count bigint`, `rating_sum bigint`, `bookmark_count bigint`, `version bigint` | CHECK các counter >= 0; đây là nguồn aggregate chính |
| `chapter_stats` | `chapter_id bigint PK/FK chapter_refs`, `view_count bigint`, `comment_count bigint` | CHECK counters >= 0 |

Comment indexes: `(chapter_id, created_at DESC, id)` WHERE status='VISIBLE' AND parent_id IS NULL để phân trang root; `(parent_id, created_at, id)` cho replies; user_id cho quản lý dữ liệu user. Parent không được đổi sau tạo; kết hợp kiểm tra cùng chapter và không tự trỏ để tránh chu trình. Xóa comment cha thành tombstone thay vì cascade mất replies. Khi ẩn/xóa comment cần cập nhật counter theo chuyển trạng thái thực tế.

Review/bookmark/comment write cập nhật stats + outbox trong một transaction. Review update dùng chênh lệch rating mới/cũ; unique constraint ngăn hai review từ request đồng thời. Xóa review phải trừ rating_sum và review_count.

book_refs/chapter_refs là FK tới bản sao cục bộ, không FK xuyên service. Event chapter đến trước book cần retry; không loại bỏ vĩnh viễn. Projection chưa có record không có nghĩa truyện không tồn tại: trả trạng thái tạm thời hoặc xác minh qua Catalog rồi retry. Book bị xóa đánh dấu refs để ẩn tương tác, sau đó xử lý cleanup theo retention. Race do độ trễ event là eventual consistency được chấp nhận, không hứa transaction toàn hệ thống.

View tracking để phase sau: cần định nghĩa một lượt xem và chống lặp trước khi tăng count. Có thể nhận event có event_id, dedup bền vững, cộng batch vào stats; không tăng PostgreSQL mỗi lần tải ảnh/refresh không phân biệt. Reading history là tính năng mới, chỉ thêm `reading_progress(user_id, book_id, chapter_id, position, updated_at)` khi có scope; PK user/book và FK cục bộ đảm bảo chapter thuộc book.

## 5. Search

Meilisearch lưu index `books` gồm `id`, `slug`, `name`, `synopsis`, `author_id`, `author_name`, `genre_ids`, `genre_names`, `tag_ids`, `tag_names`, `status_id`, `kind`, `sex`, `poster`, `published_at`, `new_chap_at`. Chỉ chứa book public chưa xóa. Read API trả document projection; không query Catalog DB để lấy lại từng hit. Kết quả có thể trễ; endpoint đọc book/chapter ở Catalog phải tự kiểm tra published/deleted.

PostgreSQL riêng cho pipeline indexing:

| Bảng | Cột chính | Mục đích |
|---|---|---|
| `book_documents` | `book_id bigint PK`, `document jsonb?`, `deleted boolean`, `source_version bigint` | Desired state, tombstone giữ version sau delete |
| `indexing_jobs` | `id uuid PK`, `book_id bigint FK book_documents`, `target_version bigint`, `status varchar(20)`, `attempts integer`, `next_attempt_at timestamptz`, `lease_until timestamptz?`, `meili_task_uid bigint?`, `last_error text?` | UQ `(book_id, target_version)`; index `(status, next_attempt_at)`; phục hồi task đang chạy |
| `processed_events` | Xem phần event chung | Dedup event Catalog |

Consumer ghi inbox/dedup + desired document + job trong transaction rồi mới ACK RabbitMQ. Indexer riêng gửi request Meilisearch, theo dõi task UID tới succeeded mới hoàn tất job. Nếu task failed phải retry/reconcile, không đánh dấu xong khi chỉ nhận HTTP accepted. Mỗi book được serialize khi submit job; bỏ version cũ và reconciliation latest desired state để request đến trễ không ghi đè bản mới. Crash giữa submit và lưu task UID có thể gửi lại; full upsert/delete idempotent và serialize theo book xử lý trường hợp này.

Đổi tên author/genre/tag cũng phải làm mới document liên quan. Catalog phát snapshot `BookSearchDocumentChanged` với revision tăng cho từng book khi bất kỳ trường index nào đổi, kể cả metadata liên kết; fan-out có thể là job bền vững. Rebuild lấy snapshot qua export API Catalog + event catch-up/watermark, build index mới rồi swap; không truy cập DB Catalog bằng credential Search.

Chưa tạo schema vector/embedding/audio: endpoint cũ đang vô hiệu hóa, cần chốt lại use case/model/chunking trước.

## 6. Ingestion

RabbitMQ chứa tín hiệu thực thi, PostgreSQL giữ trạng thái để restart vẫn tiếp tục và admin xem tiến độ.

| Bảng | Cột chính | Constraint / index |
|---|---|---|
| `crawl_sources` | `id bigint PK`, `code varchar(100) UQ`, `base_url text`, `enabled boolean`, `config jsonb` | config không chứa credential; lưu secret reference nếu cần |
| `crawl_jobs` | `id uuid PK`, `source_id bigint FK crawl_sources`, `type varchar(50)`, `target_external_id text?`, `requested_by uuid?`, `request_key varchar(255) UQ`, `status varchar(20)`, `checkpoint jsonb`, `attempts integer`, `next_attempt_at timestamptz`, `lease_owner varchar(100)?`, `lease_until timestamptz?`, `last_error text?` | CHECK status IN ('QUEUED','RUNNING','RETRY','SUCCEEDED','FAILED','CANCELLED'); index `(status, next_attempt_at)` và lease_until cho recovery |
| `crawl_job_items` | `id uuid PK`, `job_id uuid FK crawl_jobs`, `external_id text`, `payload_hash varchar(64)`, `status varchar(20)`, `catalog_id bigint?`, `last_error text?` | UQ `(job_id, external_id)`; status/attempt/checkpoint cho từng item |
| `crawl_checkpoints` | `source_id bigint FK crawl_sources`, `scope varchar(255)`, `cursor jsonb`, `version bigint` | PK `(source_id, scope)`; tiếp tục crawl qua nhiều lần chạy |

request_key phân biệt request admin để retry cùng request không tạo job trùng; một lần recrawl mới phải có key mới. Không dùng source+book làm key duy nhất vĩnh viễn vì sẽ chặn refresh dữ liệu.

Catalog chịu trách nhiệm chống import trùng ở nơi ghi cuối cùng bằng bảng nội bộ `external_book_refs(source_code, external_id, book_id FK books)` PK source/external_id và `external_chapter_refs(source_code, external_id, chapter_id FK chapters)` tương tự. external_id phải canonical trong từng source (kèm external book ID nếu chapter ID chỉ unique trong book). Worker có thể cache mapping nhưng không sở hữu identity truyện.

Khi retry sau timeout HTTP, Catalog upsert theo source/external_id và content hash để không tạo chapter trùng. Worker chỉ đánh dấu item/job succeeded sau xác nhận ghi Catalog. Claim job dùng transaction/lease, worker chết thì reaper cho retry. Ghi job + outbox cùng transaction; nhận duplicate command chỉ kích hoạt lại trạng thái chưa hoàn tất. Không ACK command rồi chỉ log: consumer skeleton hiện tại chưa đáp ứng xử lý nghiệp vụ này.

## 7. Event tables và tính nhất quán

Mỗi DB có producer nghiệp vụ thêm `outbox_events`; DB có consumer thêm `processed_events`. Không tạo database event dùng chung.

`outbox_events`: `event_id uuid PK`, `aggregate_type varchar(100)`, `aggregate_id text`, `aggregate_version bigint`, `event_type varchar(150)`, `schema_version integer`, `payload jsonb`, `correlation_id uuid?`, `occurred_at timestamptz`, `published_at timestamptz?`, `attempts integer DEFAULT 0`, `next_attempt_at timestamptz`, `lease_until timestamptz?`. Index pending `(next_attempt_at, occurred_at)` WHERE published_at IS NULL. `aggregate_id` text là envelope cho UUID/bigint, bảng domain vẫn giữ kiểu cụ thể.

`processed_events`: `consumer_name varchar(100)`, `event_id uuid`, `processed_at timestamptz`; PK `(consumer_name, event_id)`. Unique insert + thay đổi domain/projection phải cùng transaction. Duplicate trả thành công; rollback thì không đánh dấu processed. Record này không đủ bảo vệ ghi ra Meilisearch, nên Search có indexing_jobs như trên.

Outbox publisher dùng publisher confirm trước ghi published_at; crash ở giữa có thể phát trùng nên delivery là at-least-once. Version/tombstone ngăn event cập nhật cũ phục hồi dữ liệu đã xóa. Với snapshot đầy đủ, consumer chỉ nhận version lớn hơn; với delta thì phải xử lý đủ thứ tự hoặc phát hiện gap, không chỉ bỏ version thấp. Giữ lịch sử dedup/tombstone đủ cửa sổ replay; dọn outbox đã gửi theo retention và backup đã chốt, không xóa pending.

Ví dụ publish chương: Catalog commit chapter + content/stats + outbox -> RabbitMQ -> Search cập nhật desired document/job và Engagement cập nhật refs. Lỗi Search không rollback transaction Catalog; queue/job retry tự phục hồi. Đổi quyền hoặc xóa user dùng event từ Identity; không cascade database sang Catalog/Engagement.

## 8. Chuyển từ schema cũ và thứ tự thực hiện

1. Identity: `user` -> users + user_credentials + user_roles, giữ UUID/email/hash. Role enum USER/ADMIN map bảng roles; timestamps chuẩn UTC. Chọn buộc đăng nhập lại khi cutover refresh session vì schema/token contract thay đổi; cần thông báo trước cutover.
2. Catalog: giữ ID book/chapter/taxonomy và UUID author; giữ link genres/tags. `chapter_content.id` không cần làm PK nội bộ mới nhưng API tương thích có thể giữ legacy_id khi frontend còn dùng. Tính lại latest_chapter/count từ chapter thật, không cast UUID cũ sang bigint. Audit index chương <=0 trước CHECK; không tự renumber phá URL.
3. Engagement: nhập comment/review theo ID cũ nếu thực sự có dữ liệu, dựng refs trước; xử lý review trùng user/book và rating ngoài thang trước import. Recompute count/rating từ dữ liệu, counter cũ chỉ dùng để đối soát.
